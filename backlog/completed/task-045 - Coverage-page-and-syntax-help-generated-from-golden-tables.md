## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Design (TASK-033, 2026-09-27): docs/design/2026-09-27-coverage-and-syntax-help.md + copy deck §8. /coverage: every number an API field, no client sums (track x status detail per row from cells, '–' for no cell); 'Collected <from> to <to>' until /coverage exposes the window kind. API gap for the main session: additive snapshot.crawl_dates_kind and identification_citable on /coverage. /help/syntax: anchors are diagnostic codes in lower case (Help ▸ links build from the code; #slow-clauses for the two API_ codes); Messages section lists every reader-facing code with example, registry message and fix (a test fails on a missing code); Limits from /meta; generate from a committed JSON of the goldens checked by a backend contract test like wrap-golden.json.

Pre-pass: each help example carries its mode; the link reads 'Search with this example' (S15, Nit 7).

As built (2026-09-27): /coverage is a server shell over a client CoverageView (components/coverage/) that fetches GET /coverage on each visit (loading skeleton, error envelope / non-JSON / network states with Retry, no auto-retry). The report shows the snapshot facts (window worded by crawl_dates_kind; citability note when identification_citable is false), totals, the venue x year table (statuses indexed column; all-missing-abstract flag) and a per-row disclosure: track x status from cells ('–' for none, columns = statuses indexed) and each track against its official count (difference, gate verdict, citation). No client sums. Its tests render coverage-fixture.json, a real GET /coverage answer that backend test_frontend_coverage_fixture.py keeps current (regenerate: PYTHONPATH=backend uv run python -m tests.contract.coverage_fixture); a test asserts every number on the page is one of the API's. /help/syntax renders src/help/syntax-golden.json, generated by backend/tests/contract/help_golden.py from the parser (every reader-facing code: example, mode, registry message, fix), test_tokens.GOLDEN rows, spec 02's consequences table, the vocabularies, default clauses and limit constants; test_frontend_help_golden.py fails when it's stale or a reader-facing code lacks an entry, and checks POST /parse serves each message. Anchors are codes in lower case; both slow-clause codes anchor inside #slow-clauses. Limits read /meta at request time, falling back to the golden's defaults with HS-2. Checked live against the real (format-1) snapshot.
