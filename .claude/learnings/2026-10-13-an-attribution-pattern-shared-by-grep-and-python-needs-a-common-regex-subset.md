# An attribution pattern shared by grep and Python needs a common regex subset, and sent files read strictly

**Key lesson:** Write the shared attribution pattern in the subset POSIX ERE and Python `re` read alike (`.*`, never `[^\n]`, `\b` or `\s`), keep its five copies byte-identical under a test row with mutants that edit all five (`also`), and refuse any file the call reads into a message that the hook can't read or that the call writes first.

- **Date:** 2026-10-13 · **Task:** task-243 (AC5) · **Area:** tooling
- **Artifacts:** `.claude/hooks/block-ai-attribution.sh`, `.claude/hooks/lib/cmdparse.py` (`gh_subcommand`), `.githooks/commit-msg`, `.github/workflows/pr-gates.yml`, `.claude/scripts/merge_group_gate.py`, `.claude/scripts/changelog.py`, `.claude/scripts/mutate.py` (`also`), `.github/workflows/nightly.yml` (its stale check), `.claude/hooks/tests/test-openproceedings-gates.sh` (TASK-243 rows), `.claude/scripts/mutants/gates.json`

## What we set out to do
Make the shared pattern catch a generated-by footer naming an AI tool (the 2026-10-13 cloud comment) without
catching tooling text, and make the hook read the bodies `gh api -F body=@file`, `--input` and `gh issue
--body-file` send.

## What we learned
- The five copies had already drifted: `changelog.py` and the hook wrote `[^\n]*` and the three others `.*`. In
  Python these mean the same thing, because `.` stops at a newline. In grep's ERE, `[^\n]` means "not a backslash
  and not `n`". So the same text could read differently in different copies. The common subset is `( | ) [ ] * +
  ?`, a negated class spelled out (`[^a-zA-Z0-9]`), and `$`. Avoid `\b` and `\s` (BSD and GNU grep differ on
  them) and `(?:`. In Python, a set that starts with `[[` raises a FutureWarning, so write `[*_[]`. Evidence:
  scratch yes/no files run through `grep -Ei` and `python3 -W error`.
- Ending the name with a character class (`([^a-zA-Z0-9]|$)`) is what keeps "generated by airflow" and
  "generated by gptools" out. The mutant that drops it is killed only by those allow rows. "GPT4" needs its own row,
  because "gpt-4o" still matches without the version group (the `-` ends the name).
- `block-ai-attribution.sh` used to skip a message file that didn't exist or wasn't a regular file, so `cp
  draft.md body.md && gh pr comment 1 --body-file body.md` sent a body it never read. Now every file a writer's call
  reads into a message (`-F`, `--body-file`, `--notes-file`, `gh api` `-F key=@file`, `--input`, any `< file`, any
  `cat`/`head`/`tail`/`sed` file) is read whole or refused (exit 2). A file the call writes first is scanned as the
  command's own text when that is what writes it (`cat > f <<'EOF'`, `printf '…' > f`: the raw command is scanned
  anyway), and refused when anything else writes it (`cp`, `jq … > f`, `… | tee f`). So is a file option with no
  value (`--body-file <(…)`, whose `<(…)` the walk drops). `/dev/null` reads as empty. Strictness has a cost the
  reviewers found by probing: the second reading with HOME/TMPDIR as '' turns
  `"$TMPDIR/msg"` into `/msg`, so that reading has to skip a path that isn't a file, and `0<&3` is a descriptor
  copy, not a file named `3`.
- A pipe can feed a gh writer reading stdin (`jq -Rs '{body: .}' msg.md | gh api … --input -`, `git diff
  --no-index /dev/null msg.md | gh pr comment 1 --body-file -`). Any other program but gh run on a file in such a
  call is refused, unless the writer has its own `<`, `<<` or `<<<`, which is scanned. Exempting git as well let
  `git diff` through, and not exempting the writer's own heredoc refused `python3 x.py && gh … --body-file - <<EOF`.
- A one-file mutant of a pattern kept identical in five files is killed by the identity row alone, whatever the
  behaviour rows test. `mutate.py`'s `also` applies the same edit to every copy. With it, a review found gaps the
  identity row had hidden: no row for `codex` without a vendor, and none for a body with no final newline (the `$`).
- Under a load average of 200 to 300 (several sessions at once), `mutate.py`'s baseline flaked
  (`test-mutate-run.sh` timing, `test-dependabot.sh`) and printed nothing more than "baseline is not green".
  Running `--match <label> --jobs 1` again gave a clean verdict.

## Dead ends — don't repeat these
- One pattern file read by all five places. The cloud routine runs dev's `.githooks` from a scratch directory
  (`git archive … .githooks`), `test-changelog.sh` copies `changelog.py` alone, and CI's inline step runs before
  any script. Each copy has to stay self-contained, so the single source is a test row that checks they are identical.
- Quoting the footer in a commit or PR body. The pattern now matches the repo's own descriptions of the incident.
  Write "a generated-by footer naming Claude Code" instead.

## Decisions (and what would change them)
- A footer counts only before an AI or tool name: claude, anthropic, openai, (chat)gpt, copilot, gemini, bard,
  codex, llm or ai, optionally after an article and a vendor. This is the owner's ruling (TASK-243). A new
  assistant name goes into all five copies at once.
- `gh api` counts as a write with `--input`, a method other than GET, or a field unless every method given is GET
  (gh puts fields in the query string then); a bundled `-iF` is split. gh's `-R`/`--repo` between group and verb
  (`gh pr --repo o/r create`) is skipped, which also closed that form in `require-review.sh`.
- Additive only (coordinator, 2026-10-13): dev's hook and this one were run over the same full case table, and no
  row that dev blocks is allowed here (99 rows go from allow to block).
- Known limitations, left to CI's check: inline interpreter code that opens a file, a `git tag`/`git notes`
  message fed from a pipe, and a program's own output-file option (`sort -o`, `curl -o`, `dd of=`, `sed -i`).
- An inline write is scanned as text, but the file is read too when it exists: the write may append, not run
  (`false && printf … > f`, an `if`) or run alongside (`&`). A group's `{ …; } > f` has no argv and is not inline.
