# In a root npm workspace the frontend's tools live in ./node_modules, and every "frontend/node_modules" check silently skips

**Key lesson:** With `workspaces: ["frontend"]` at the repo root, `npm ci` hoists everything to `./node_modules` (only Vite's cache ever appears in `frontend/node_modules`), so gate on the root `node_modules/` and make `make lint`/`test` fail, not skip, when `frontend/` exists without it; and run `next typegen` before `tsc --noEmit`, or `PageProps`/`LayoutProps` don't exist.

- **Date:** 2026-09-27 · **Task:** task-039 · **Area:** frontend
- **Artifacts:** `Makefile` (`frontend-deps`), `.claude/hooks/autofix.sh`, `.github/workflows/{lint,test}.yml`, `frontend/next.config.ts`, `frontend/src/lib/search-state.ts`

## What we set out to do
Stand up the Next.js skeleton as an npm workspace member, wire prettier/eslint/tsc/vitest into `make lint`,
autofix and CI, and write the URL↔state reducer.

## What we learned
- **Hoisting moved every tool.** After `npm install` at the root, `frontend/node_modules` did not exist
  (later only `.vite/` appeared there), yet the Makefile, `autofix.sh` and its case-table row all tested
  `frontend/node_modules`. The old `make lint` would have passed without running a single frontend check.
  The hook now tests `$root/node_modules` (mutant "autofix looks for node_modules in frontend/", killed),
  and `make fmt/lint/test` depend on `frontend-deps`, which fails with "run make sync" instead of skipping.
- **`npx --no-install` from `frontend/` finds the hoisted bins** (`npx --no-install next --version` →
  16.3.6), so the Makefile can keep `cd frontend && npx --no-install …`.
- **`tsc --noEmit` alone fails on Next 16 pages** (`TS2304: Cannot find name 'PageProps'`): the route-type
  globals are generated into `.next/types` by `next typegen`/`next build`. `make lint` and the `typecheck`
  script run `next typegen` first; `next-env.d.ts` is regenerated by it, so it is gitignored.
- **Standalone output follows the tracing root.** With deps hoisted, `outputFileTracingRoot` (and
  `turbopack.root`) must be the workspace root; the server then lands at
  `.next/standalone/frontend/server.js`, not `.next/standalone/server.js`, and `.next/static` must be
  copied beside it (`npm start` does; the Docker image must too).
- **CI's schema-freshness step would have fired on the skeleton.** It was gated on
  `frontend/package.json` existing and ran `op openapi` + `npm run gen:api`, neither of which exists before
  TASK-040/035. It is now gated on `frontend/src/api/schema.ts`.
- **`create-next-app` 16 writes `AGENTS.md`/`CLAUDE.md` into the app** (and `next dev` re-adds the block).
  They were removed; the repo's own CLAUDE.md governs.
- `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` compile cleanly with Next 16, next-themes
  and the shadcn `cn` helper.

## Dead ends — don't repeat these
- npm 10.8 (Node 20) failed the first workspace install with `Cannot read properties of null (reading
  'edgesOut')`; npm 11 installed it. The lockfile is v3 and `npm ci` on CI's Node 22 reads it.
- `next/font/google` (the scaffold default) fetches fonts at build time; the Docker build must work
  offline, so the skeleton uses system font stacks.

## Decisions (and what would change them)
- The reducer takes a server-supplied `FilterClause {source, span, values}` and splices `q`; it never
  parses. It throws on a stale clause, an emptied field or a non-identifier value rather than no-op. If
  `/parse` grows a per-field clause summary (TASK-078), the type is derived from the schema instead.
- `mode` is part of the result-set key with `q` (it changes how `q` is read); `sort`/`page` are view state.
- Node 22 via `.nvmrc`, because Vitest 5 requires ≥ 22.12 and CI already used 22.
