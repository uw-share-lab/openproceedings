# CodeMirror 6 + Lezer (spec 05 §Components 1, grammar from spec 02)

## The rule
**The server's parser is authoritative. The client grammar only highlights; it never decides.** No
error, warning or "did you mean" originates in the browser. Lezer is error-tolerant and will happily
build a tree for garbage; that tree colours tokens and nothing else.

## File layout (as built, TASK-041)
| File | Holds |
|---|---|
| `frontend/src/editor/lang/query.grammar` | Lezer grammar: `@top Query { lexeme* }` over external tokens only, so no rule can reject input and the tree never has an error node |
| `frontend/src/editor/lang/lex.ts` | the lexeme scanner: `lexer.py`'s token boundaries in **code points**, for highlighting (no diagnostics, no normalisation); the concept-group builder also uses it to write each term as exactly one lexeme (`src/builder/terms.ts`, `write.ts`; TASK-043), so a change here must keep `lexer-golden.json` passing for both |
| `frontend/src/editor/lang/tokens.ts` | the `ExternalTokenizer`: reads the doc via `InputStream.peek` as code points, calls `lex.ts`, converts the end to UTF-16 |
| `frontend/src/editor/lang/lexer-tables.json`, `lexer-golden.json` | **generated** from `lexer.py` by `backend/tests/contract/test_frontend_lexer_golden.py` (`cd backend && uv run python -m tests.contract.test_frontend_lexer_golden --write`); the backend test fails when either is stale |
| `frontend/src/editor/lang/parser.ts`, `parser.terms.ts` | generated by `npm run gen:grammar --workspace frontend`, committed; `grammar.test.ts` fails when stale; never hand-edit |
| `frontend/src/editor/lang/index.ts` | `LRLanguage` + `styleTags` + `HighlightStyle` (`--syn-*` tokens) |
| `frontend/src/editor/parse.ts` | `postParse` → `ParseOutcome` (parsed / too_large 413 / refused 429·503 / no_answer non-JSON / unreachable), keyed by `(q, mode)`; only an abort throws |
| `frontend/src/editor/use-parse.ts` | TanStack queries `["parse", q, mode]`: the draft's debounced 250 ms (`useDraftParse`), the searched `q`'s (`useSearchedParse`) |
| `frontend/src/editor/diagnostics.ts` | ordering, span conversion (through `spans.ts`), repeat grouping, summary counts, Help anchors |
| `frontend/src/editor/complete.ts` | completion from `/meta` only |
| `frontend/src/editor/query-editor.tsx` | the React wrapper: keymap, `setDiagnostics` for the text the answer belongs to, `aria-label="Query"` |

**Squiggles are pushed, not linted.** The row, summary, tree and squiggles all need the same `/parse`
answer, so the editor does not use `linter()`: `useDraftParse` owns debounce, cancellation (TanStack aborts
the older key's request) and staleness (an answer is stored under the key it was asked for), and
`QueryEditor` dispatches `setDiagnostics` only while the document equals the answer's `q`. `lintGutter()`,
`lintKeymap` (F8, Mod-Shift-m) and `previousDiagnostic` (Shift-F8) work on that state unchanged.

**Tests.** `lex.test.ts` and `grammar.test.ts` run `lexer-golden.json` (every lexer/parser golden input, the
Trust-Evals strings, probes and 400 seeded random strings). Component tests stub the API with
`frontend/src/test/api-stub.tsx` and advance fake timers with its `pass(ms)`, which interleaves separate
`act()`s with real event-loop turns (learning 2026-09-27, editor highlighter).

## Grammar mirrors spec 02
- Operators are **uppercase only**: `AND`, `OR`, `NOT`, `NEAR/<int>` via `@specialize` on the word token
  (case-sensitive), so `and`/`or` stay `Word`. Also `|` and leading `-`.
- `Field` = exactly `title abstract venue year track status source`, followed by `:`. Any other
  `name:` is `UnknownField` (as `lexer.py` emits a FIELD lexeme for it), left uncoloured: the server's
  FIELD_UNKNOWN says what is wrong. A malformed `NEAR/x` is `BadNear` (the lexer emits no lexeme there).
- `Phrase` opens with any of `"`, `“ ”`, `„ ‟`, `＂`, `« »`, `「 」`, `『 』` and closes only with a quote of
  the same family: `"“”„‟＂` close each other; `« »`/`» «`, `「 」` and `『 』` pair with themselves (a
  backslash-escaped quote doesn't close it). The highlighter must match the server exactly, including the
  errors for a quote touching a word outside and for `model(s)` (`lexer.py`); NFKC look-alikes of
  syntax characters (`（ ）｜：－＊＂`) are syntax, as in `lexer.py`; `Wildcard` = word ending in `*` or `$`; `Range` = `INT..INT`; parens.
- Words must accept the same character set the backend lexer does (Unicode letters, digits, `-`, `'`,
  LaTeX `\cmd{…}`, `$…$`). When `backend/src/openproceedings/query/lexer.py` changes, this file changes in
  the same PR.

## Highlight tags (`@lezer/highlight`)
| Node | Tag | Note |
|---|---|---|
| `AND OR NOT NEAR` | `t.logicOperator` / `t.operatorKeyword` | never colour-only: also bold |
| `Field` | `t.propertyName` | |
| `Phrase` | `t.string` | |
| `Wildcard` | `t.special(t.variableName)` | underline dotted — expansion happens server-side |
| `Range`, INT | `t.number` | |
| parens | `t.paren` | enable `bracketMatching()` |
Colours come from `ui-design-system` tokens so both themes pass contrast.

## Diagnostics from the server
- Debounce 250 ms (spec: ≤300 ms felt latency; measured 261–272 ms against `op serve`, TASK-041), then POST
  `{q, mode}` to `/api/v1/parse`; a newer draft cancels the older request, and an answer is shown only for the
  text it was asked about (see "Squiggles are pushed, not linted" above).
- Map `errors → "error"`, `warnings → "warning"`, `translations → "info"`; message = server message
  verbatim, `source` = its code. Never rewrite server wording, and never parse it: an action that needs data
  from a diagnostic reads a field (`withParentheses` in `diagnostics.ts` splices `WARN_MIXED_AND_OR`'s
  `reading` over its span; TASK-099).
- Spans: diagnostic spans are half-open `[start, end)` code-point offsets over `q` (spec 04
  §Conventions). Convert them to CodeMirror positions (UTF-16) with the one shared helper
  (`src/api/spans.ts`, `.claude/skills/nextjs-conventions/SKILL.md`), never a second conversion. Clamp to
  doc length; a zero-width span gets width 1 (one code point) so it is visible.
- A `/parse` that doesn't parse (429, 503, a non-JSON 5xx, no answer) draws no squiggle and puts one line in
  the row, "The query couldn't be checked: …", with Check again: never silence, never a client-side guess. A
  413 is the design's ED-11 error line.

## Autocomplete (`@codemirror/autocomplete`)
- Field names from `/meta` field vocabulary, completing `field:`.
- After `track:` / `venue:` / `status:` (including inside `(…)`), values from `/meta` vocabularies.
- Uppercase operators offered only after a complete operand. Never auto-insert on Enter-to-search;
  Enter submits, `Ctrl-Space` opens completion.

## Keyboard
Do **not** add `indentWithTab`: Tab must leave the editor (see `accessibility`). `Enter` and `Mod-Enter`
submit, `Shift-Enter` inserts a newline, F8 / Shift-F8 move between diagnostics, Mod-Shift-m opens the lint
panel. No `closeBrackets`: the editor never types what the reader didn't.

## Testing the grammar
1. Token parity (`lex.test.ts`, `grammar.test.ts`): every case in `lexer-golden.json` (generated from the
   backend's own golden lists and `backend/tests/fixtures/queries/trust-evals.txt`, so the sides cannot drift)
   gives the server lexer's classes at its spans, with no `⚠` node.
2. `parser.ts` is regenerated in the test and compared with the committed file.
3. Operator case: `a or b` has no `Or` node; `a OR b` does. Incremental reparses equal fresh parses.
