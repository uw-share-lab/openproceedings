# CodeMirror 6 + Lezer (spec 05 §Components 1, grammar from spec 02)

## The rule
**The server's parser is authoritative. The client grammar only highlights; it never decides.** No
error, warning or "did you mean" originates in the browser. Lezer is error-tolerant and will happily
build a tree for garbage; that tree colours tokens and nothing else.

## File layout
| File | Holds |
|---|---|
| `frontend/src/editor/lang/query.grammar` | Lezer grammar (source of truth for highlighting) |
| `frontend/src/editor/lang/parser.ts` | generated by `@lezer/generator` — commit it or build it in `prebuild`; never hand-edit |
| `frontend/src/editor/lang/index.ts` | `LRLanguage` + `styleTags` + `LanguageSupport` |
| `frontend/src/editor/lint.ts` | `/parse` → `Diagnostic[]` |
| `frontend/src/editor/complete.ts` | completion sources |
| `frontend/src/editor/lang/test/*.txt` | Lezer file tests |

## Grammar mirrors spec 02
- Operators are **uppercase only**: `AND`, `OR`, `NOT`, `NEAR/<int>` via `@specialize` on the word token
  (case-sensitive), so `and`/`or` stay `Word`. Also `|` and leading `-`.
- `Field` = exactly `title abstract venue year track status source`, followed by `:`. Anything else
  before `:` is a `Word` (the server will report the unknown field).
- `Phrase` opens and closes with any of `"`, `“ ”`, `„ ‟`, `＂`, `« »`, `「 」`, `『 』` (unpaired; a
  backslash-escaped quote doesn't close it); NFKC look-alikes of
  syntax characters (`（ ）｜：－＊＂`) are syntax, as in `lexer.py`; `Wildcard` = word ending in `*` or `$`; `Range` = `INT..INT`; parens.
- Words must accept the same character set the backend lexer does (Unicode letters, digits, `-`, `'`,
  LaTeX `\cmd{…}`, `$…$`). When `backend/src/openproceedings/query/lexer.py` changes, this file changes in
  the same PR.

## Highlight tags (`@lezer/highlight`)
| Node | Tag | Note |
|---|---|---|
| `AND OR NOT NEAR` | `t.logicOperator` / `t.operatorKeyword` | never colour-only: also bold |
| `Field` | `t.propertyName` | |
| `Phrase` | `t.string` | |
| `Wildcard` | `t.special(t.variableName)` | underline dotted — expansion happens server-side |
| `Range`, INT | `t.number` | |
| parens | `t.paren` | enable `bracketMatching()` |
Colours come from `ui-design-system` tokens so both themes pass contrast.

## Linting from the server
- `linter(source, { delay: 250 })` from `@codemirror/lint` (spec: debounce 250 ms, ≤300 ms felt latency).
- The source POSTs `{q, mode}` to `/api/v1/parse` with an `AbortController`; abort the previous request;
  drop any response whose doc no longer equals the text that was sent.
- Map `errors → "error"`, `warnings → "warning"`, `translations → "info"`; message = server message +
  fix hint verbatim. Never rewrite server wording.
- Spans: diagnostic spans are half-open `[start, end)` code-point offsets over `q` (spec 04
  §Conventions). Convert them to CodeMirror positions (UTF-16) with the one shared helper
  (`src/api/spans.ts`, `.claude/skills/nextjs-conventions/SKILL.md`), never a second conversion. Clamp to
  doc length; a zero-width span gets width 1 so it is visible.
- Network failure → one "info" diagnostic "parser unavailable", not silence and not client-side guessing.

## Autocomplete (`@codemirror/autocomplete`)
- Field names from `/meta` field vocabulary, completing `field:`.
- After `track:` / `venue:` / `status:` (including inside `(…)`), values from `/meta` vocabularies.
- Uppercase operators offered only after a complete operand. Never auto-insert on Enter-to-search;
  Enter submits, `Ctrl-Space` opens completion.

## Keyboard
Do **not** add `indentWithTab`: Tab must leave the editor (see `accessibility`). Bind `Mod-Enter` and
`Enter` (single-line) to submit.

## Testing the grammar
1. `fileTests` from `@lezer/generator/test` over `lang/test/*.txt` (input → expected tree).
2. Fixture parity: every Trust-Evals string and every valid case in the backend golden/fixture files
   parses with **no `⚠` error node**. Read the fixtures from `backend/tests/fixtures/` rather than copying
   them, so the two sides cannot drift.
3. Operator case: `a or b` has no `Or` node; `a OR b` does.
