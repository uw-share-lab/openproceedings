# A bare `<` in abstracts: the crawl-cache replay and the rebuild (TASK-209)

2026-10-07 · TASK-209 (owner-approved 2026-10-07; found during TASK-208) · built from the shared cache by this
branch's `html.py` on origin/dev `80d83a5a`; `data/indexes/current` was not moved (it stays `4646c7547fe7`) and
no snapshot or index was deleted.

Until this change, every Python release read a `<` followed by a letter as a tag, so an abstract lost the text up to
the next `>`: `if a<b and c>d then` read `if ad then`. A tag that never closed did worse. On a PMLR page,
`$1<p<\infty$. For …` opened an element that ran to the end of the page, so the abstract lost its second half and
picked up the page's "Cite this Paper" BibTeX and Endnote text. `html.escape_bare_lt` now escapes every `<` that
doesn't start a real tag before the parser sees it (spec 01 §Pipeline step 2). Real markup is copied unchanged.
The escape is plain Python, independent of the interpreter's `HTMLParser`, and the replay below is byte-identical
on 3.12.9 and 3.12.15.

## What stays a tag

The rule (`html.escape_bare_lt`, spec 01 §Pipeline step 2) can't tell `a<b>c` from bold markup, and reads it as a
browser does: `ac`. A `<` before a known element name whose attributes are all HTML attribute names is a tag too (`x<p title>`; `x<p for q>` stays text, since `q` is no attribute name). Two odd real-markup shapes now read as text: a
bare event-handler attribute (`<p onclick>`; accepting every `on…` name would take prose such as `<b only>` for a
tag) and an unquoted attribute value holding a `<` (`<a href=x<y>`). The replay found none of these shapes in a changed record; every committed proceedings fixture page is
unchanged by the escape (`test_html.py`).
