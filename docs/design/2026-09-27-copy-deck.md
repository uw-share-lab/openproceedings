Status: **reviewed**, handed off after the heuristic pre-pass · Backlog: TASK-033 (AC#3) → TASK-041–045, TASK-133 (§9), TASK-100 (the strings TASK-041–044 added) · Owner: ux-writer · Standard: `ux-writing`

How to read this deck:
- **Home** says where the string lives. *Registry* = the backend diagnostic registry (parser, engine and
  API messages; the frontend shows them verbatim and never rewrites them). *Reducer* =
  `frontend/src/lib/search-state.ts` (already built and pinned by its tests). *New* = a frontend string this
  design adds; the implementing task owns it and pins it in a test.
- `{field}` is an API value, `<…>` a computed display value. Numbers use `toLocaleString("en-US")`
  (`1,340`), never abbreviations.
- Glossary terms used: query, canonical query, identification string, index version, papers (UI) / records
  (PRISMA and methods text), match, excluded, limit, default filter, expansion, translation, warning, error,
  search record, reproduced, drifted, mismatch. Checked against `ux-writing` §Glossary; no new term was needed
  except **unclassified** (already the spec's word for `unknown` buckets) and **identification string** (spec
  05's word, used as the label for `identification_query`).
